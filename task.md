Юинг В.К. ИС-122Выбранна тема: Разработка информациионной системы для организации учета смен, записей, задач и рабочего времени в малом бизнесе 

Актуальность темы: Малый бизнес в сфере услуг (парикмахерские, салоны красоты, мастерские, сервисные центры) сталкивается с необходимостью оперативного управления записями клиентов, рабочими сменами сотрудников, задачами и учетом времени. На практике такие процессы часто ведутся вручную, в мессенджерах или разрозненных таблицах, что приводит к ошибкам, потере данных и снижению эффективности управления.
Существующие программные решения либо избыточно сложны (например, конфигурации 1С), либо имеют высокую стоимость и требуют длительной настройки. В связи с этим актуальной является разработка веб-ориентированной информационной системы, обеспечивающей простой, доступный и централизованный учет процессов малого бизнеса с возможностью масштабирования и монетизации.

Цель и задачи дипломной работы 
Разработка информациионной системы для автоматизации учета записей клиентов, смен сотрудников, задач и рабочего времени малого бизнеса с разграничением прав доступа и возможностью онлайн-мониторинга — В ПРОСТРАНСТВЕ ВЕБ. 
Итог: Сайт-платформа для онлайн работы с платформой, что позволит и на ПК работать и на телефоне.

Задачи работы
1.	Проанализировать предметную область малого бизнеса в сфере услуг.
2.	Определить функциональные и нефункциональные требования к системе.
3.	Спроектировать архитектуру клиент-серверного приложения.
4.	Разработать модель базы данных и реализовать ее в PostgreSQL.
5.	Реализовать веб-приложение с использованием Angular.
6.	Обеспечить разграничение ролей пользователей (владелец, сотрудник).
7.	Реализовать календарь записей и систему справочников.
8.	Разработать механизмы регистрации, авторизации и приглашений.
9.	Предусмотреть основу для монетизации платформы.
10.	Провести тестирование и оценку эффективности системы.

Объект и предмет исследования
Объект исследования:Процессы управления записями, задачами и рабочим временем в малом бизнесе.
Предмет исследования:Методы и средства разработки веб-ориентированных информационных систем учета и планирования.

Краткое описание разрабатываемой системы
Разрабатываемая платформа представляет собой веб-информационную систему с двумя типами пользователей:
Типы пользователей
	Владелец бизнеса (администратор)
	Создает рабочий стол (пространство бизнеса)
	Приглашает сотрудников
	Управляет календарем, справочниками и настройками
	Назначает записи и задачи сотрудникам
	Управляет платными функциями
	Сотрудник
	Работает только в рамках приглашенного стола
	Видит свои записи и смены
	Может создавать записи только для себя
	Имеет доступ к справочникам в рамках прав
	Отслеживает время работы 
Каждому пользователю при регистрации присваивается уникальный идентификатор.
Основной функционал системы
1. Рабочий стол бизнеса
	Централизованное пространство для управления бизнесом
	Роли и права доступа
	Список сотрудников
	Справочники
	Расширение монетизацией
	Календарь работы
2. Календарь записей
	Представления: год, месяц, неделя, день
	Запись содержит:
	Клиента
	Время приема
	Услуги
	Назначенного сотрудника
	Автора записи
	(Может еще учитывать амортизацию)
	Администратор может управлять всеми записями
	Сотрудник — только своими, но может просматривать других сотрудников (Например для замены смены с напарником)
3. Учет задач и смен
	Назначение задач сотрудникам
	Контроль выполнения
	Привязка к датам и времени
	Разделения: Личные задачи, TO-DO, Общие задачи, Распоряжения и правила
4. Справочники
	Клиенты
	Услуги
	Сотрудники
	Материалы
	Прочие повторяющиеся данные (От рода деятельности: Можно будет добавить питомцев, или учет снаряжения)
Использование справочников ускоряет создание записей и снижает количество ошибок.
5. Монетизация
	Базовый бесплатный функционал (Ограниченеи в кол-во справочников, кол-во участников, финансововм мониторинге)
	Расширенные возможности доступны после оплаты владельцем стола (Подписка на месяц, 3 месяца, 6 месяцев, Год)
	Подготовка архитектуры под платежные сервисы (Иммитация оплаты покупки расширения стола


Архитектура системы
Тип архитектуры: клиент–серверная, многоуровневая
Уровни архитектуры
1.	Клиентский уровень (Frontend)
	Веб-приложение Angular -
	UI-компоненты PrimeNG
	Взаимодействие с сервером через REST API
Либо уже похожее что то из WEB (Например Python)
Либо мобильная разработка (Kotlin, Flutter) – Как представленн на прототипе (Скриншоты ниже)
2.	Серверный уровень (Backend) — Любой сервер на локальной машине который будет обарабатывать запросы к БД
	Обработка бизнес-логики
	Авторизация и аутентификация
	Работа с базой данных
	Сервисы уведомлений
3.	Уровень данных
	PostgreSQL
	Хранение пользователей, записей, задач, справочников
	Процедуры
	Логика учета данных (Просрочки, переполнение, ошибок)
